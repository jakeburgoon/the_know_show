# The Know Show v1.10.0 — Feedback pilot setup

This is a complete cumulative application, based on v1.9.2. There are still 74 categories and 1,046 playable questions. Deploy between shows.

## One-time setup (existing Supabase and Vercel project)

1. In Supabase, select the existing Know Show project. Open **SQL Editor → New query**. Copy and run the entire contents of `supabase/upgrade_v1_10_0.sql`. It adds only the `know_show_feedback` table, indexes, and server-only access permissions. It can be run again safely. Do not delete or recreate your rooms or members tables. For a fresh installation only, `supabase/schema.sql` contains the full schema including feedback.
2. In Vercel, open the existing project, then **Settings → Environment Variables**. Create `DEVELOPER_PASSWORD`. Use a password manager to generate a random, unique password of **at least 24 characters** (32 or more recommended). Save it privately. Choose Production (and Preview if you plan to test there). Do not use `NEXT_PUBLIC_`, put the value into GitHub, share it with players, or change your existing Supabase secrets. The dashboard and player feedback remain disabled until this variable is configured correctly.
3. Unzip the complete application and replace the corresponding files at the root of the existing GitHub repository using the same deployment process as before. Make sure new folders and files are included. Commit and verify the Vercel deployment succeeds. If you add the password after deploying, redeploy so Vercel uses it.
4. Go to your existing game URL and append `/developer`. Enter the password you set in step 2. You should see the private dashboard and initially zero reports. The route is deliberately not linked from the public site. A signed, HttpOnly session cookie expires in eight hours; sign out when done. HTTPS is required in production. If you rotate the password, existing sessions and pending feedback invitations are invalidated.

## How players use it

- After the answer reveal, tap the gold flag and **Question feedback**. Multiple reasons can be selected, plus optional comments. Available for regular and Final Word questions on individual player/team devices; hosts can also flag from Host View. The public TV display has no feedback control. The report includes the exact question ID and wording, category, difficulty, expected answer, bank hints and alternatives, and the reporting contestant's answer and scoring outcome as available when the dialog was opened. It does not attach names or emails. The answer-review/dispute button is unchanged and remains the way to ask the host to change scoring.
- The modal stays open when the show advances to another phase within the room. The first question-feedback request while results are still showing triggers a shared five-second break; later requests for the same question do not extend it. The dialog announces when play resumes and stays open for unfinished feedback, so a player who keeps it open may miss the next question. Close it when ready to continue. Submissions use a signed, two-hour invitation; duplicate reports from the same participant for the same question in a show are ignored. The invitation is generated only after reveal, not before an answer is shown. A new rematch is a separate show. If the host closes the room and navigates everyone home, an unsent dialog may be lost; send feedback before starting a new room.
- At the Curtain Call, beneath play-again controls, tap **Help us improve The Know Show! Share your feedback.** Every joined player/team and authenticated host can optionally rate enjoyment, describe problems, suggest new categories, or leave comments. No extra account is required. Players can submit any nonempty combination of fields. Reports are private; please avoid entering personally identifying information in the text. No player names, email fields, or tokens are stored in the feedback table. A show ID and pseudonymous deduplication key are stored. Raw written answers and free text can contain personal information if someone enters it.

## Developer workflow

- Filter by All feedback, Show feedback, Flagged questions, or Category suggestions. The default status filter is Unresolved (New + Under review).
- Change status to New, Under review, Resolved or No change needed. Use All statuses to see resolved reports. For a question, choose View reports for this question to see related reports together. Reports are paginated 100 at a time.
- Export matching feedback to CSV. By default the export includes all unresolved reports, not just the first page. Choose a filter to export a narrower set or choose All statuses to export everything. If over 10,000 matches, narrow the filter. The export contains question context, reasons, ratings, comments and status, and neutralizes spreadsheet formula prefixes. You can upload the CSV to ChatGPT for future review and release planning. Store exports privately.
- The dashboard does not yet collect statistics for every question played or track average accuracy, timing or hint usage across all players. It contains voluntary reports only. Those analytics and player accounts remain future developments.

## Verification checklist before sharing

- Confirm Vercel builds successfully and the footer shows v1.10.0.
- Open `/developer` in a private browser: wrong password must not allow sign-in; correct password should load the dashboard. Sign out and confirm refreshing does not expose reports. Only a server-side service key can directly access the feedback table.
- Start a two-player show. Open one regular result, submit a flag with two reasons, then check the dashboard for the exact question and your own answer. Verify scores and the host's dispute workflow still work. Repeat for a Final Word question. Check the dialog stays open after the results advance.
- Finish a show, submit category suggestions and an enjoyment rating from a player phone, verify the dashboard status filters, mark a report resolved, and export all statuses to CSV. Try a rematch and verify feedback from it is distinct.
- Test on the iPhone and desktop layouts you use. This release was validated with local engine/security unit tests and source/UI contract checks, not a live Supabase deployment or a complete Next.js production build. For wider public launch, consider additional login rate limiting (e.g. Vercel Firewall), a privacy notice and retention/deletion process; the present login adds a fixed delay for unsuccessful attempts but is not a distributed rate limiter. The randomly generated password is important.
