# The Know Show v1.13.0 — Replayability and exposure tracking

## Update existing installation (v1.12.1)

1. Finish any active shows. In your existing Supabase project, open SQL Editor → New query. Paste and run `supabase/upgrade_v1_13_0.sql` in its entirety. It is additive, transactional and safe to rerun. RLS is enabled and anonymous/authenticated browser access is revoked on the new tables. Existing room, player, feedback and category-control data are not deleted. If prompted to enable RLS, do so.
2. Optional but recommended: run `supabase/verify_v1_13_0.sql` in a separate query. The synthetic records are rolled back. Look for the PASS notice or no SQL error. This is a real database smoke test, not run in the authoring environment.
3. Upload the update-only package contents to the existing GitHub repository root, preserving folders. No deletion needed. Alternatively use the cumulative package. No new Vercel environment variables; the existing server-side Supabase service-role key and developer password are used.
4. Wait for Vercel production deployment to succeed, then create a new show. Sign in to `/developer` and open **Show & question statistics**. Refresh after the first question reveal; verify that it appears before anyone answers. Finish the question and refresh; accuracy, hint use, answer format and time should be recorded. Test a dispute correction. Finish the show and rematch; verify distinct show IDs and new question selections. A skipped question is logged separately because the result reveals its answer; it does not contribute to accuracy.

## Selection rules

History is retrieved from Supabase at each show start, including rematches. A missing migration or failed history read blocks show start with an explanatory error rather than using a blank history. First use imports surviving old host room histories (up to 80) and the local browser backup where available. Old history is seeded once; historical accuracy/response data are not reconstructed. The room revision and its exposure journal are saved in one database transaction. A stale revision cannot create another exposure. Server responses render only committed game state.

The host browser is a history scope and a proxy for untracked guests. Adult guests may opt in to remembering questions on their browser when joining; this is a random browser identifier, not an account, name or age. Distinct known browser histories are combined. If a host participates on the host device, the host scope is already included. Every question actually exposed is saved to each participating tracked browser scope, including Final Word. Shared devices represent a single history, not individual people. Guests who don't opt in are covered only by the host's history. Clearing browser storage, using another device, or overlapping shows can cause repeats; concurrent shows use a snapshot of history at their respective start times. No accounts, family profiles or age collection yet.

- Questions: unseen across all tracked histories first; if exhausted, fewest tracked histories that have seen the item; then oldest last exposure across those histories; random tie-breaking. Among unseen items, prefer avoiding an answer that has appeared recently in another category. Final Word uses the same unseen / fewest / oldest rule and excludes categories on either board.
- Categories: always eight choices, four selections; category cooldown weights retain the previously approved recent-selection/recent-offer preferences. Prioritize categories with unseen questions at all three levels. If necessary, fill from categories with two, one, then zero fresh levels. Reserve one eligible seasonal choice even if all eligible seasonal categories are exhausted. Other seasonal categories compete normally. No disabled, out-of-season or Round 1-selected categories in Round 2. The statistics dashboard records each offer's unseen counts, weight and seasonal guarantee.

## New recorded data

- Per show: unique ID (rematches separate), start and completion time, player/team seat count and mode, categories offered and selected, category selection diagnostics, number of tracked histories, app version.
- Per question exposure: question and category IDs, difficulty, round, reveal timestamp, unseen candidates at selection, tracked histories that have seen it, and repeat status. One row per show/question. Exposures are recorded at reveal, before answers are resolved. Questions placed on a board but never revealed do not count as exposures.
- Resolved question stats: attempted and correct, written vs multiple choice, hint users and counts, eligible answering seats with no answer, response time (including deadline autosubmission, excluding pauses), host scoring changes, skipped and unresolved status. Per-attempt metrics are stored without names, raw typed answers or individual IDs; canonical multiple-choice option index is saved (0=correct, 1–3=distractors). The original room snapshots and voluntary feedback are unchanged and may contain display names/answers as before. No new age or demographic data collected. Guest browser history is pseudonymous, not anonymous; adult guest opt-in is not a full parental consent or privacy compliance system. Review privacy notice, data retention/deletion and applicable children's privacy requirements before broader public rollout.
- Dashboard: recent 50 shows, offered/selected categories and offer diagnostics, question selection reasons, avoidable repeat count, aggregate accuracy by format, hint counts, response time, overrides, and filtered CSV export. Accuracy denominators are submitted answers; missing answers are reported separately. Team nonresponses count only eligible turns in newly tracked data. Unresolved abandoned questions count as exposures without final performance statistics. Developer previews do not enter these stats.

## Validation and limitations

The focused TypeScript engine compilation passed. 85/86 engine tests passed, including all eight new exposure/selection tests. The only existing failure remains the previously known Machu Picchu overlap in Famous Landmarks (currently disabled). 55/55 UI/source-contract tests passed. All 1,072 question records, flags, artwork, and existing functionality are preserved (question bank version metadata updated). No live Supabase database or full Next production build was available for verification. The optional database smoke test and a deployed two-player show are important acceptance tests. This release doesn't eliminate repeats from missing or untracked histories or concurrent shows. No account/family profile or age-specific stats have been implemented.
